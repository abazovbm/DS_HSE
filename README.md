# Классификация программного кода с определением нелегитимного функционала

Итоговый проект курса «Введение в анализ данных», ВШЭ.

## Задача

Бинарная классификация Python-кода:
- **Класс 0 (легитимный)** — обычные Telegram-боты, веб-приложения, утилиты;
- **Класс 1 (нелегитимный)** — боты-криптоказино: рулетка, кости, слоты,
  crash-игры с приёмом криптовалют (USDT, TRX, BTC) в качестве ставок.

Подобные боты массово публикуются на GitHub. Автоматический детектор
такого кода может использоваться платформами хостинга и службами безопасности.

## Структура проекта

```
project/
```

## Как запустить

### 1. Клонировать репозиторий и установить зависимости

```bash
git clone <repo-url>
cd project
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Распаковать датасет (если архив)

Если получили проект с архивом `code_samples.tar.gz`:
```bash
cd data
tar -xzf code_samples.tar.gz
cd ..
```

Либо сгенерировать датасет заново:
```bash
cd data
python generate_dataset.py
cd ..
```

### 3. Запустить ноутбук

```bash
jupyter notebook code_classification.ipynb
```

Выполнить ячейки сверху вниз (Cell → Run All).

### 4. (Опционально) Собрать реальные данные с GitHub

```bash
export GITHUB_TOKEN=ghp_xxx     # https://github.com/settings/tokens
cd data
python github_scraper.py
```

После этого нужно вручную просмотреть собранные файлы в `data/raw/`,
удалить дубликаты и неподходящие репозитории, затем добавить их в основной
датасет (обновив `code_dataset.csv`).

## Ключевые методологические решения

### 1. Гибридные признаки

- **TF-IDF на нормализованном коде** (1- и 2-граммы, ~3000 признаков).
  Перед векторизацией удаляются комментарии и docstrings, строковые
  литералы заменяются на токен `<STR>`, числа — на `<NUM>`. Это убирает
  «шум» из идентификаторов и URL.
- **7 структурных признаков**: длина, количество импортов и функций,
  количество подозрительных слов, факт обращения к платёжным API
  (web3, ccxt, tronscan, адреса вида `0x...`, `T...`), факт использования
  random.

### 2. GroupKFold по шаблону

Стандартный random split в этой задаче даёт data leakage: вариации
одного шаблона попадают и в train, и в test. Поэтому для CV
используется `GroupKFold`, где группа — это тип шаблона
(`legit_weather_bot`, `illegit_dice_bot` и т.д.). Каждый шаблон
целиком попадает либо в train, либо в test — это моделирует реальную
задачу: классификация **новых типов** ботов.

В ноутбуке показана разница: random split → F1 = 1.000 (иллюзия),
GroupKFold → F1 ≈ 0.85–0.95 (реалистично).

### 3. Граничные примеры в датасете

Чтобы классификатор не учился по тривиальным триггерам, в легитимный
класс намеренно добавлены:
- крипто-трекер курсов (использует те же crypto-API, но не казино);
- торговый бот для биржи (тоже работает с USDT, web3);
- менеджер кошельков (использует web3.py);
- образовательная игра в кости (содержит слова `bet`, `dice`, `roll`);
- платёжный процессор (Stripe, обрабатывает деньги).

В нелегитимный класс добавлены замаскированные примеры:
- бот, выдающий себя за «авто-трейдера», но являющийся казино;
- минимизированная версия с однобуквенными именами без явной лексики
  (без слов `casino`, `jackpot`).

## Результаты

На отложенной тестовой выборке (шаблоны, не виденные при обучении):

| Модель | F1 (нелегит) | Precision | Recall |
|---|---|---|---|
| Logistic Regression | ~0.90 | высокий | средний |
| Random Forest | ~0.93 | высокий | высокий |
| Gradient Boosting | ~0.91 | средний | высокий |

Точные числа зависят от random_state и состава тестового сплита —
смотри ноутбук.

## Направления развития

1. **Word2Vec / эмбеддинги токенов кода** — устойчивость к синонимам.
2. **Признаки на основе AST** — более точный анализ структуры кода.
3. **Pre-trained code-эмбеддинги** (CodeBERT, GraphCodeBERT).
4. **Расширение на другие языки** (JavaScript для веб-фронтендов казино).
5. **Активное обучение** — целенаправленная разметка пограничных случаев.
